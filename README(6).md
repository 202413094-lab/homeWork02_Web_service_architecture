# 교내 특강 신청·승인 서비스

웹서비스설계 과제 2 · 장환희

학생은 특강을 신청하거나 본인의 대기 신청을 취소할 수 있다. 담당 운영자가 승인을 취소하면 같은 특강에서 가장 먼저 신청한 대기자 한 명이 자동 승인된다. 신청 상태와 변경 이력은 SQLite에 함께 저장된다.

## 설치 및 실행

Node.js **24.x**와 npm이 필요하다. 개발에 사용한 버전은 **v24.15.0**이다. 서버는 Express 5.3.0을 사용하며 로그인한 사용자는 JWT로 인증한다. 별도 DB 서버 설치는 필요 없다.

1. 저장소를 복제한 뒤 터미널에서 `package.json`과 `package-lock.json`이 있는 폴더를 연다. 배포본 구조에서는 `cd starter`로 이동한다. 저장소 최상위에 두 파일이 있다면 그 위치에서 진행한다.
2. 다음 명령을 순서대로 실행한다.

```sh
node --version
npm ci
npm start
```

3. 브라우저에서 http://127.0.0.1:3000 에 접속해 아래 연습 계정으로 로그인한다. 서버를 종료하려면 터미널에서 `Ctrl+C`를 누른다.

| 계정 | 역할 |
| --- | --- |
| `alice`, `bob`, `charlie` | 학생. 특강 신청 및 본인의 대기 취소 |
| `manager1` | 행사 1 담당 운영자. 정원 2명 |
| `manager2` | 행사 2 담당 운영자. 정원 1명 |

모든 연습 계정의 비밀번호는 `Classroom123!`이다.

## DB 초기화

초기화하면 해당 복제본의 신청 내역과 변경 이력이 삭제된다. 기존 데이터를 보존하면서 재현하려면 새 폴더에 저장소를 복제하고 `npm ci`를 실행한 뒤 진행한다.

1. 서버를 종료한다.
2. `npm run db:reset`을 실행하고 확인 메시지에 `RESET`을 입력한다.
3. `npm start`로 서버를 실행한다. 기존 데이터의 재시작 후 유지 여부를 검증할 때는 초기화 없이 서버만 재시작한다.

## 변경 파일과 구현 결과

주요 변경 파일은 `src/application-service.js`이다(배포본 기준 `starter/src/application-service.js`). 제공된 인증·조회 API, 화면, DB 스키마와 저장 함수를 사용하여 다음 네 기능을 구현했다.

| 함수 | 완료 여부 | 동작 |
| --- | --- | --- |
| `apply` | 완료 | 학생과 중복 여부를 확인한 후 PENDING 신청과 APPLY 이력을 저장한다. 취소 이력이 있는 학생도 같은 특강에 재신청할 수 없다. |
| `cancel` | 완료 | 학생 본인의 PENDING 신청을 CANCELLED로 변경하고 CANCEL 이력을 기록한다. |
| `approve` | 완료 | 담당 운영자, 대기 상태, 잔여 정원을 확인한다. 승인 인원이 정원 미만이면 APPROVED로 변경하고 APPROVE 이력을 기록한다. |
| `revoke` | 완료 | 담당 운영자가 승인 취소 사유를 입력하면 APPROVED를 REVOKED로 변경한다. 같은 특강의 PENDING 신청 중 신청 시각이 가장 빠른 한 명을 승급하며, 시각이 같으면 신청 ID가 작은 사람을 선택한다. |

각 함수는 상태 변경과 이력 저장을 한 트랜잭션으로 처리한다. 자동 승급 이력의 `causeHistoryId`는 원인이 된 승인 취소 이력의 ID를 가리킨다. 중간 저장이 실패하면 승인 취소와 승급, 관련 이력을 모두 롤백한다. 대기자가 없으면 승인 취소만 확정하고 `promoted: null`을 반환한다.

## 검증

설치를 마친 뒤 `package.json`이 있는 폴더에서 실행한다.

```sh
npm test
npm run test:assignment
```

- `npm test`는 제공된 기반 기능 4건을 검사한다.
- `npm run test:assignment`는 필수 시나리오 T01~T32를 임시 DB에서 검사한다. **구현 후 확인한 결과는 32건 통과, 0건 실패**이다. 롤백 검사 중 표시되는 `TEST_INJECTED_FAILURE`는 의도적으로 발생시킨 저장 오류이며, 통과 여부는 각 테스트 결과에서 확인할 수 있다.
- 선택 심화 동시성 검사는 `npm run test:advanced`로 별도 실행한다.

화면에서는 학생·운영자 계정으로 신청과 승인, 오래된 화면의 승인 거부, 서버 재시작 후 이력 유지, 대기자 유무에 따른 승인 취소를 확인할 수 있다. API 계약은 실행 폴더의 `docs/API.md`, 제출 보고서 경로는 저장소 최상위 기준 `docs/report.pdf`이다.
